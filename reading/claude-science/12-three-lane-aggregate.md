# 你的 Claude Science 多久没更新了

Claude Science 绿皮书第 12 期 · 2026-08-21

Claude Science 绿皮书 12 · 更新一次

![](/claude-science/paper12/cover.png)

**不想看故事的，先照这两条做**

1. 把 CSA 启动器更新到最新发布版。
2. 把它里面那个 Claude Science 底座，更新到你能兼容的最新版。

这是两件事，不是一件。只做第一件，你的内核还停在原地。

为什么值得花二十分钟：官方从 6 月 30 日到 8 月 7 日的 38 天里发了 7 个带条目的版本——一个月不动，就落下五六版。

## 一、有一天，我成了别人的下载源

因为大家都清楚的原因，国内没法直接下载 Claude Science。后来国内那个 Workbody 把这一步的下载源指到了我这边——绿皮书那个仓库，CSA 的发布包。

我是收到一句反馈才知道的：怎么你们还是这么旧的版本？

![成了别人的地基，就得先看看自己多久没动过](/claude-science/paper12/became-download-source.jpeg)

*成了别人的地基，就得先看看自己多久没动过*

自己用旧版本，那是自己的事。别人从你这里拉包，就不是了。这篇的起点就是这句反馈。

## 二、「我一直在更新你这个启动器啊」

上周那场线上分享讲到升级，有人接了一句：我一直在更新你这个启动器啊。

他说的是实话，他确实一直在更新 CSA。他没更新的是里面那个 CS。

![外壳擦得锃亮，里面那台还在睡](/claude-science/paper12/engine-still-asleep.jpeg)

*外壳擦得锃亮，里面那台还在睡*

同一场里还有一位同学问：更新是在哪里更新？我装好的时候显示的就是 0.1.25。我说那你不用更新，今天这一遍是给最早那批装机的人看的。

两个人问的其实是同一件事：大部分人不知道自己在更新哪一层。

## 三、两层，升级动的是里面那一层

Windows 上跑这套东西是两层：外面是启动器 CSA，负责把它在 Windows 上拉起来、把路铺通；里面是官方的 Claude Science 本体，干活的是它。你在界面上看到的 0.1.x，说的是里面那一层。

仓库里的升级规矩写得很直：安装或升级必须下载完整 ZIP 和同名 SHA-256 文件（校验用的那串指纹码），不要只替换 EXE。

我把这个包拆开看过。里面除了那个二进制，还有一批本地打的补丁、一份存着会话与设置的 SQLite 数据、一个常驻后台的 daemon、一条把请求转进 WSL 的 Bridge，以及你已经存进去的 API Key。只复制那个 exe，这些都不会跟着动。

覆盖式升级最危险的也不是程序起不来，是新版把数据库迁移了——真要回退，光换回旧二进制已经不够。

这就是为什么「把 Claude Science 升到最新」没法单独执行，它得跟着外面那层一起换。

## 四、七周，六个版本

官方 6 月 30 日发出第一版，编号 0.1.14；首版之后又发了六个带更新条目的版本，最新那个是 8 月 7 日的 0.1.27。中间公开出现过的编号是 0.1.15、0.1.16、0.1.17、0.1.18、0.1.21。

我把编号排了一遍：0.1.14 到 0.1.27 之间横跨 14 个，官方只给这七个写了更新条目，剩下一半——0.1.19、0.1.20、0.1.22 到 0.1.26——都没有。不是不存在，是没写。所以「我到底落后了几个版本」这个问题，光看日志是数不出来的。

*七周六个版本，站在第一级和第七级不是一件事*

落后七周是什么概念，看 7 月 8 日那一版就够了：空闲会话在后台空转、照样计费，这个 bug 在那天被修掉。你要是还停在第一版，它一直没被修。

## 五、要新，但不能太新

翻更新记录的时候我看到过一条：0.1.2x 里动了 Windows 虚拟机相关的组件。那一次我没有完全跟进，理由就是兼容。

判断用的尺子是仓库里写死的五条：下载包校验 SHA256、设置 schema 迁移、更新前备份、启动后健康验收、一键回退。缺一项，就不该去替换正在用的那个版本。

最后停在 0.1.25。v0.1.4 把内核从 0.1.15-dev 追到它，v0.1.5 的发布说明第一句仍然是「继续锁定 Claude Science 0.1.25」。同一个内核连着两版被拿来当底座，这就是我要的证据。

做 v0.1.4 那会儿，官方的 latest / stable 其实已经走到 0.1.27 了，我还是推荐 0.1.25。我推荐它的理由只有一条：它过了上面那套兼容验证。

稳定版不是版本号落后一点，是你知道自己验证过什么，也知道哪些还没验证。

还有一句得说清楚：0.1.25 在官方更新日志里没有独立条目，但它确实存在——官方 manifest（官方自己那份版本清单文件）里能查到，构建指纹 b7190511，7 月 24 日构建。查不到的只是它的功能说明。

按位置推，它手上有 0.1.21 那批东西——上下文保留、Compute 监控、记忆按项目隔离；没有 0.1.27 的跨项目通知和计划确认。

那要不要现在就追到 0.1.27？我的答案是先别动生产环境。它值钱的地方是三样：计划先批准后执行、跨项目通知，以及一个日志里没写、扒二进制才看到的 `mcp-env-check`，Connector 出问题时的自查命令，0.1.25 里没有。

但 CSA 到现在锁的还是 0.1.25，兼容验证只做到这里。真要升，先开个并排目录跑，别替掉正在用的那个。

## 六、CS 这半年在往哪边长

一条线是活在 agent 之间转手：本地 Subagent、沙盒外的外部 agent 协作、Connect 那套双向链路，都是把任务派出去再收回来。7 月 21 日那版的项目级记忆隔离、8 月 7 日那版的计划先批准后执行，都是同一个方向上的零件。

另一条线是 Windows。官方到今天写的仍然是 macOS 13 以上和 Linux x64，Windows 得靠 WSL 绕过去。绕的原因不复杂：真实主链路就跑在 WSL 里，Bridge、运行时和日志全收口到那一边，才不会出现面板提示成功、请求其实没切过去的情况。

但同一家的另一个产品已经走完这一步了：Claude Code 现在官方支持 Windows 原生安装，PowerShell、CMD、WinGet 三条命令任选一条，Windows 10 1809 以上就能装，二进制带官方签名。代价是原生模式下没有沙箱，要沙箱还得回 WSL2。

Claude Science 这边更有意思。我把 0.1.25 和 0.1.27 的二进制拉出来对了一遍命令表：0.1.25 只有 `serve`、`status`、`update`、`import` 四条；0.1.27 是八条，多出一个 `mcp-env-check`，还多出 Windows native 的 `sandbox`、`install`、`uninstall`。

命令表从四条长到八条，多出来的这四条是悄悄加进去的，官方更新日志里一个字都没写。

所以现在准确的说法是：Claude Code 已经有 Windows 原生版，Claude Science 官方仍然只发 mac 和 linux——但它自己的二进制里，Windows 原生那套命令已经躺在那儿了。

哪天 Claude Science 把这一层收掉，这个启动器的一半理由就没了。这句话上个月还只是我的猜测，现在有命令表撑着。

## 七、手把手：一次升级二十分钟

第一步，下整包。约 80MB 的发行包先下到「下载」，再复制进工作目录，别只拿那个 exe。

第二步，核对 SHA-256。上周演示的时候我说过一句「一般不核对也行」，这句我在这里改口：核对一次十秒钟，装错一次半小时。

第三步，把升级交给 agent，自己只做监督。它会先给一份计划，你审完再让它跑，二十到三十分钟。

第四步，验收。刷新之后打开是新的版本号，进去看一眼三个模型位还在不在。

![四步：接包、验指纹、交出去、验收](/claude-science/paper12/four-steps-upgrade.jpeg)

*四步：接包、验指纹、交出去、验收*

出问题一般就三个地方：后台常驻程序、桥接服务、虚拟机本身，重装都很快。

## 八、把这四步写成一份 prompt

上面那四步，真正要你动手的只有第三步里的那份指令。这份我写好了，改掉尖括号里的内容就能用。

```text
角色：你是本机的升级执行助手。
目标：把 CSA 启动器与其内置的 Claude Science 内核，升级到我指定的目标版本。

【环境】
- 系统：Windows 11 + WSL2 Ubuntu-24.04
- 当前启动器版本：<填>
- 当前内核版本（界面上显示的 0.1.x）：<填>
- 目标启动器版本：<填>
- 目标内核版本：<填>
- 安装包完整路径：<填>
- 同名 SHA-256 校验文件路径：<填>

【硬性禁令，任何一条都不许违反】
1. 不替换原目录，新版本装到并列的新目录
2. 不覆盖任何现有文件
3. 保留安装包，结束后不要删
4. 不卸载旧版本
5. 不修改端口，Bridge 固定 127.0.0.1:9876

【动手之前必须先做的五件事】
1. 校验安装包 SHA-256，与同名校验文件比对，不一致立刻停下来告诉我
2. 备份 %APPDATA%\ClaudeScienceAssistant\settings.json
3. 对本地 SQLite 数据做一次一致性快照；新版可能迁移数据库，只留旧二进制是退不回去的
4. 记录旧版本目录的完整路径，作为回退点
5. 检查磁盘剩余空间是否够解压

【工作方式】
先输出完整执行计划：每一步做什么、动哪些目录、失败了怎么退回。
输出计划后停下，等我回复「开始」才能执行。
每完成一步报一次，不要跑完再汇报。

【完成后逐条回报验收结果】
1. 启动器版本号是否为目标版本
2. 内核版本号是否为目标版本
3. Bridge 的 /health 是否返回正常
4. default / vision / fast 三个模型位是否都在，聚合模式是否仍然生效
5. 旧版本目录是否完整保留，回退路径是什么

【失败处理】
任何一步出错立刻停止，不要自行换第二套方案，把报错原文贴给我。
```

这份 prompt 里最值钱的一句是「输出计划后停下」。少了它，你就不是在监督，是在祈祷。

## 总结

第一，你要更新的是两层。启动器在外，内核在里，只更新外面那层等于没更新。

第二，先去看一眼你在哪一版。落后三天和落后七周，是两件事。

第三，不必追最新，追到你能兼容的那一版，然后锁住它，把版本号写进自己的发布说明里。我锁的是 0.1.25；0.1.27 在并排目录里试，暂不替掉生产。

第四，升级这件事本身可以交出去。你要做的是写清楚五条禁令、审一遍计划、验四项结果。
