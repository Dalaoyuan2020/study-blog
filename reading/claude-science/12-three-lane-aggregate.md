# 先把内核追上，再让它看图：连升两版分别改了什么

Claude Science 绿皮书第 12 期 · 2026-08-14

![](/claude-science/paper12/cover.png)

**先说结论**

1. 「Claude Science 助手」这个启动器，和它拉起来的「Claude Science 本体」，是两条独立的版本线，各有各的号——升级助手不等于本体也跟着变。
2. 这次连升两版，干的是两件不相干的事：v0.1.4 追的是 Claude Science 本体自己的更新节奏，顺手把「认出旧版本」这一步交给了程序；v0.1.5 是主力模型换成 DeepSeek 之后，为了不丢视觉能力，另外给三个模型槽分别接了上游。
3. 三档不是三个 Key 轮流用。本地仍然只有一个 Bridge，Claude Science 发哪个槽位的请求就走哪条路，我不用动手。
4. 视觉档我绑的是 MiniMax，图片输入还没过真机。这条写在正文里，不放到结尾。

## 一、你升的，不是它启动的

官方下载页上，Claude Science 只有三个包：Mac（Apple Silicon）、Mac（Intel）、Linux。没有 Windows。

（图待补：no-windows-build.png）

我用的是 Windows，只能把 Linux 版塞进 WSL 里跑。这就带出一个容易搞混的地方：我在助手界面点的「升级」，升的是 Claude Science Assistant 这个启动器；WSL 里跑起来的 Claude Science 本体，是另一条版本线，二进制随包发布，包不重打，它不动。

助手自己有一串版本号，本体又是另一串，两条线各走各的——助手升一版，不代表本体也跟着动。

![两个版本号各走各的，不要混着说](/claude-science/paper12/launcher-vs-kernel.png)

*你升的是助手，它启动的是本体——两个版本号各走各的，不要混着说*

## 二、v0.1.4：先让内核追上，顺手把「认出旧版本」交给程序

官方那边什么时候动过、动了什么，我查不到。它还是 beta，只放一个 latest 下载。我翻了官方的 release notes，从去年 8 月到现在，Claude、Claude Code、Cowork 都有条目，Claude Science 一条没有。想知道手上是哪一版，只能打开助手看状态栏——状态栏里那一串是完整的 build 号，格式大概是 `0.1.15-dev.20260701.t220242.shaaa553de` 这样，日期、时间、commit 哈希全在里面。

（图待补：six-status-panel.png）

*六项状态栏全在画面里，Claude Science 那格的版本号看得清*

所以更新这件事只能靠助手自己扛。v0.1.4 这一版，一是把支持库更到位，把 Claude Science 本体那条落后的线追上来；二是把「认出旧版本、自动接管」这一步交给了程序——新版本启动时会自己找到旧目录里正在跑的 Bridge，做受控接管，不用我手动去点。完整的「应用内自动下载、静默替换、一键回滚」还没做，助手自己的文档里也把这条明确列在「尚未完成，不得写成已上线」那一栏。所以现在这套是：手动下载，自动接管，手动验收。

升级方式是「并排」，不是覆盖安装：

1. 下载完整的新 ZIP，解压到一个新目录。不能只换 EXE，也不能把散文件盖进正在跑的旧目录
2. 新版本认出旧目录的 Bridge，受控接管，顺手校验 `source_path` 和配置版本。防的是旧解压目录里的进程冒充当前版本
3. 同一台机器、同一个用户，继续读原来那份配置和系统里存的 Key，订阅不用重加
4. 六项状态全绿，再加一次真实对话验收通过，才删旧目录。不通过就退回旧的

![四步走完才算升级完成，不通过退回旧目录](/claude-science/paper12/side-by-side-upgrade.png)

*新目录解压 → 受控接管 → 复用配置 → 验收才删旧，不通过就退回旧目录*

## 三、v0.1.5：主力换成 DeepSeek，图看不了，所以搭了个聚合

平时我拿 Claude Science 读文献、整实验记录，后面接的是 DeepSeek。便宜，一百万输入 token 一毛四美金，够用。

卡住的地方是截图。一张谱图、一张显微照片扔进去，它答不上来——DeepSeek 没有视觉。想让它看图，得退回助手界面，把 API Key 换成另一家，等 Bridge 重启，再回去接着问。问完想省钱，还得换回来。

原因写在 v0.1.3 的更新记录里，一句话：

> API Key 列表按添加顺序展示，同时只激活一条配置。

一条配置生效，就是全部原因。Claude Science 里有三个模型槽——Opus、Sonnet、Haiku，分别对着深度思考、图像与多模态、日常快问。三个槽，一条 Key，只能全指向同一家。这家便宜，三个槽都便宜；这家不看图，三个槽都不看图。

![一条 Key 走天下 vs 三档并挂](/claude-science/paper12/one-key-vs-three-lanes.png)

*一条 Key 走天下 vs 三档并挂，本地永远只有一个 Bridge*

v0.1.5 加的是聚合模式。三档，对着 Claude Science 那三个槽：

| 档位 | 对应槽位 | 我配的 | 单价（每 1M） |
| --- | --- | --- | --- |
| 决策 | Opus | DeepSeek V4-Pro 0813 | \$0.435 / \$0.87 |
| 视觉 | Sonnet | MiniMax | 待补 |
| 日常 | Haiku / Fast | DeepSeek V4-Flash | \$0.14 / \$0.28，缓存命中 \$0.0028 |

（图待补：aggregate-config-ui.png）

*决策 / 视觉 / 日常三档下拉 + 方案一方案二，点确认切换才真的生效*

它不是三个 Key 轮流用。本地还是只有一个 Bridge，里面存两张表：`model_aliases` 记 Claude 的槽位对应哪条 route，`aggregate_upstreams` 存三条各自独立的密钥、Base URL 和模型名。聚合模式下 `force_model` 强制留空——这个字段原本的意思是「所有请求都用这个模型」，不清空，三档会被压成同一个。

Claude Science 发 Opus 请求，走决策那条；发 Haiku，走日常那条。我不用点任何东西。

上面还叠了一层：方案一 / 方案二，各存一整套三路映射。点方案只是预选，界面高亮，运行状态不变；点「确认切换」才真的换，切完核对 `source_path`、配置版本号，再发一次真实的上游请求，任何一步失败就报错回滚。

这套方案切换留到下一篇细说，那篇讲怎么配才划算。

v0.1.5 顺手还修了一个问题，我以前撞见过，一直以为是自己手滑：改完配置，界面提示保存成功，实际请求还是走老模型。

原因很直白。改配置之后有一步「重启 Bridge」，旧逻辑第一行判断是：Bridge 没在运行？那就直接返回成功。

对这个函数自己来说，逻辑没错——没跑起来的东西不用重启。对用的人来说，这是假的成功：新配置确实写进了文件，Bridge 没有加载。

v0.1.5 把这个早退删了。不管 Bridge 当时在不在跑，都执行一次 Bridge-only 的 restart 或 start，起来之后调 `/health`，把返回里的 `_csa_revision` 跟本地配置版本号对一遍，对不上就报错。加 Key 那里也补了一个 20 秒硬超时，不让它无限转圈。

![旧逻辑判假成功，新逻辑核对 revision 才算数](/claude-science/paper12/silent-success-timeline.png)

*旧逻辑 Bridge 没在跑就直接判成功，新逻辑要核对 revision 才算数*

这条从 v0.1.3 修到 v0.1.5，中间隔了两版，病根是同一个：软件把「我执行完了」当成「事情成了」。做工具的人容易踩这个坑，因为他知道那一步为什么可以跳过；用的人不知道，只看见一个绿色的成功提示。

## 还没验完的

视觉档绑的是 MiniMax。我翻了 7 月 11 号那轮供应商实测记录，MiniMax 那一栏只确认了基础连通，图片输入没测过。v0.1.5 自己的文档里，「待人工复验」第一条就是这件事：把视觉角色绑到真实支持图片输入的订阅，发一张图，确认实际路由和回答。

三条路里，决策和日常都跑过，视觉这条目前只过了单元测试。发稿前我会补一次真图测试，结果放进下一篇。

## 下一篇

三档配好之后怎么用、一个月花多少。DeepSeek 8 月初预告了 API 全系列涨价，没给日期也没给新价——正好拿方案一 / 方案二试一次，涨价当天能不能一键换掉整套。
